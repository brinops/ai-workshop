# Claude Code Subagents: від тікета до дії

25 слайдів і нотатки ведучого українською. Орієнтир — 55 хвилин. Учасники пропонують правки в чаті або на папері. Ведучий вносить дві зміни й запускає їх із підготовленого репозиторію.

## Запуск презентації

З каталогу `presentation` виконай:

```bash
npm ci
npm run dev
```

- [Слайди](http://localhost:3030/) · [Режим ведучого з нотатками й таймером](http://localhost:3030/presenter/).
- Стрілки перемикають слайди, пробіл відкриває наступний крок, `f` вмикає повноекранний режим.
- `npm run build` оновлює статичну збірку в `dist/`.
- `npm run export` створює PDF, `npm run export:clicks` додає кожен крок розкриття, `npm run export:png` рендерить усі слайди. Якщо Chromium відсутній, виконай `npx playwright install chromium`.

## Підготовка ведучого

Перевір Claude Code і Python на ноутбуці ведучого, відкрий Jira Workflow і прив’яжи Slack до потрібного профілю. Збережи повідомлення до й після змін і приклад погодженого запису в Jira. Підготуй завершений HTML-прогін через **Use page example** і перевір, що в **Timeline → Agent activity** є деталі інструментів та структурований результат. Відкрий поряд файли агента й skill. [Чекліст інтеграції](../docs/specs/jira-slack-workshop-integration-checklist.md)

З кореня репозиторію виконай команду й збережи результат:

```bash
cd backend
.venv/bin/python -m app.workshop_exercise --reply incomplete | tee /tmp/workshop-before.txt
```

Локальна команда генерує уточнення й чернетку. Для запису в навчальну Jira відкрий окремий живий тікет і пройди схвалення в Slack.

## Порядок показу

1. **Покажи весь шлях тікета.** На схемі пройди від Slack-уточнень за потреби й схвалення версії до автоматичного плану, ручного запуску виконання, тестів, рев’ю та завершення. Далі прочитай опис подвійного бронювання й запитай, якої деталі бракує.
2. **Покажи skill.** Відкрий Tone of Voice й визнач із залом одну зміну, яку видно в готовому повідомленні. Наприклад, «кожне питання в окремому нумерованому рядку». Повтори команду з тим самим `--reply incomplete`, тим самим агентом і моделлю. Зістав форму, факти й наступну дію. [Tone of Voice](../.claude/skills/workshop-tone-of-voice/SKILL.md)
3. **Покажи сабагента.** Відкрий Investigation. Поясни роль, вхід, дозволені інструменти й вихід. Попроси зал запропонувати, яку відсутню деталь повернути першою. Внеси одну правку й повтори кейс зі збереженим форматом результату. У **Timeline → Agent activity** розгорни `Read` та `Structured output` і зістав прочитаний файл із доказами та уточненнями агента. [Investigation Agent](../.claude/agents/workshop-investigation.md)
4. **Пройди схвалення наживо.** Відповідай у Slack на питання бота, прочитай актуальну чернетку і натисни «Схвалити». Через **Timeline → All events** зістав схвалену версію, запис у Jira й підтвердження в треді. Перевір, що погоджений блок додався один раз і статус Jira залишився `New`.
5. **Покажи другий маршрут на готовому HTML-прогоні.** Порівняй із бронюванням. Для сторінки уточнюємо мету й вміст, для багу — умови відтворення. У **Plan** перевір маршрут `static-page`, у **Diff** покажи HTML і CSS, у **Validation** — результат перевірок. У **Timeline → Agent activity** відкрий `Bash` із викликом скрипта Reviewer. Покажи `SKILL.md`, runbook і файл у `scripts/`. [Skill для перевірки сторінки](../.claude/skills/workshop-page-review/SKILL.md)

Якщо Slack або Claude Code затримується, покажи збережені повідомлення й готові прогони. Так зал побачить і схвалення, і результат виконання в межах виділеного часу.

**Що працює краще для вправи.** Одна правка за прогін і заздалегідь сформульована умова успіху. Якщо одночасно змінити тікет, модель і skill, важко зрозуміти причину відмінності. У перевірках розрізняй, що виконав агент, що засвідчив hook, що пропустила схема й що справді записав бекенд.

## Стандарт для агентів і skills

Використовуй `Purpose → Variables → Instructions → Workflow → Runbooks`. У `Variables` описуй значення, які читає модель, або поля й ліміти з контракту. У розділі `Runbooks` вкажи умову вибору гілки й посилання на її файл у `runbooks/`. У файлі опиши умову, дію й приклад через `IF / THEN / EXAMPLES`. Для headless-запуску runner має скопіювати папку скіла й дозволити читання файлів, на які він посилається.

Для агента вкажи роль, вхідні дані й точний формат відповіді. У YAML на початку файла зберігай налаштування Claude Code, зокрема дозволені інструменти та підключені skills. У skill описуй повторювану процедуру або правила, які агент застосовує у своїй роботі.

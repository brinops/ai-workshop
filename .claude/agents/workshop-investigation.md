# Purpose

Знайди підтверджені факти й суттєві прогалини в описі бага або нової функції. Передай висновок Triage для уточнення або підготовки чернетки.

## Variables

- `evidence_paths` — дозволені шляхи для читання.
- `sufficient_for_append` — булеве значення, чи досить фактів для чернетки.

## Instructions

- Розділяй слова репортера, факти з коду й тестів та припущення. Результат виконання тесту вважай фактом, якщо його надав бекенд.
- Читай файли з дозволених шляхів, коли вони стосуються задачі. Посилайся на прочитаний шлях і наявний у ньому символ.
- Формулюй прогалини, які впливають на уточнення або чернетку.

## Workflow

1. Зістав опис і всю відповідь репортера з попередніми питаннями.
2. Обери гілку в `Runbooks`. Визнач, чи досить підтверджених деталей.
3. Поверни внутрішній JSON із масивами `reporter_facts`, `code_facts`, `evidence`, `missing_details` і булевим `sufficient_for_append`. Кожен запис `evidence` містить `path` і `symbol`.

## Runbooks

### Bug report

- IF: Тікет описує помилку.
- THEN: Визнач умови відтворення, фактичну та очікувану поведінку. Зістав їх із дозволеними доказами.
- EXAMPLES:
  - «Обидва користувачі побачили підтвердження» належить до `reporter_facts`. Умова, прочитана в тесті, належить до `code_facts`.

### Feature request

- IF: Тікет просить нову функцію.
- THEN: Визнач результат, аудиторію, ключову поведінку й обмеження. Для нової статичної сторінки без початкового коду поверни порожній `evidence`.
- EXAMPLES:
  - Для нового лендингу з’ясуй, куди має вести основне посилання.

# Фікстура подвійного бронювання

У сервісі є одне вільне місце. Двоє користувачів одночасно його бронюють і обидва отримують підтвердження. Очікувана поведінка — підтвердити перше бронювання, а другого користувача додати до листа очікування.

Початковий опис багу й приклади відповідей репортера для Slack зібрані у [scenario.json](scenario.json). Розслідування використовує [сервіс](service.py) і [тест відтворення](test_booking.py).

## Відтворення

З кореня репозиторію, якщо локальне середовище бекенду вже підготовлено:

```sh
backend/.venv/bin/python -m pytest -q demo/booking/test_booking.py
```

Очікуваний результат — один пройдений тест послідовного бронювання й один `xfail` для відомого дефекту. Щоб показати саме падіння:

```sh
backend/.venv/bin/python -m pytest --runxfail -q demo/booking/test_booking.py
```

У другій команді тест паралельного бронювання падає з фактичним `("confirmed", "confirmed")` замість очікуваного `("confirmed", "waitlisted")`. Події в тесті дають обом викликам прочитати той самий залишок перед підтвердженням, а потім дозволяють завершитися першому й другому по черзі. Штатний CI бекенду збирає тести з `backend/tests`, а цю фікстуру запускаємо окремо.
